# ToScreen 产品演进与架构演进路线图 (Updated)

基于最新对齐的产品愿景，我们将项目的开发生命周期重构为更具商业级 SaaS 逻辑的**三大阶段**。当前我们的绝对重心是“打地基”。

## 宏观演进路线

### 🧱 阶段一：打地基 (Foundation & Core Features) - **当前阶段**
*   **目标**：把编辑器的基础功能做扎实，把底层架构做稳定，完全复刻并吃透 Screen Studio 的核心编辑体验。
*   **核心模块**：
    *   [x] 绝对坐标系与渲染分离架构。
    *   [x] 时间轴基础：Zoom 的反向绑定、快捷键分割片段 (`S`)。
    *   [x] **视频裁剪架构重构 (Video Trim)**：解决目前底层 Export 与 UI 交互割裂的遗留问题（已通过 isSkippingRef 解决）。
    *   [ ] 多轨道图层管理：文字、图形标注的层级与时间轴对齐。

### ✨ 阶段二：特效库与 3D 包装 (VFX & 3D Mockups)
*   **目标**：突破传统录屏工具的视觉天花板，融合 **Rotato 的 3D 包装能力** 与 **Jitter 的动效逻辑**。
*   **核心模块**：
    *   **3D 设备模型包装 (Rotato-style)**：将底层连续视频作为动态材质（Texture），无缝映射到高精度的 iPhone/Mac 3D 模型上进行空间运镜。
    *   **独立矢量动效层 (Jitter-style Cursor)**：彻底剥离原生卡顿鼠标。通过在录屏阶段（底层 API）**隐藏系统原生光标**，并在编辑器中读取 `clicks.json` 坐标，重新绘制一个 60fps 的矢量光标。支持独立的缓动曲线、点击果冻抖动（Jiggle physics），并支持集成额外的 UI 动画图层。
    *   高级全局运镜特效库（平移、景深特效）、后期级动态运动模糊 (Motion Blur)。

### 🤖 阶段三：AI 自动化 (AI Auto-Editing)
*   **目标**：引入生成式 AI，彻底改变交互范式，打造次世代编辑体验。
*   **核心模块**：
    *   基于鼠标点击图谱 (`clicks.json`) 的智能自动运镜 (Auto-Zoom) 算法进化。
    *   引入 Whisper 等大模型能力，实现“基于语音文本的自动剪辑”。
    *   自动消除无声片段、停顿词。

## 阶段一急需用户决策：重构 Trim（裁剪）逻辑

### 最终决定：采用方案 B（打块跳过模式）作为终极底座

**决策依据**：根据你未来要整合 **Rotato (3D设备贴图)** 和 **Jitter (独立矢量图层)** 的宏大产品愿景，我们**绝对不能**将底层视频像剪映那样物理切碎。
*   要在 3D 模型上映射动态画面，底层必须是一整块连续的视频纹理（Texture）。
*   要做 Jitter 逻辑的鼠标动效，时间轴必须是连续的全局数学模型。

因此，我们的第一阶段“打地基”的最硬核任务已经确定：**重写底层的播放引擎，实现“打块跳过区间”的参数化无缝跳跃逻辑。**

## 商业护城河分析：ToScreen vs 纯 AI 自动化脚本 (如 Hyperframer)

> [!NOTE]
> 面对市面上涌现的“丢进 IDE 靠 AI 自动出视频”的极客工具，ToScreen 的核心商业壁垒在于：

1.  **受众降维打击**：ToScreen 面向的是广大的创作者、营销人员和非技术创始人。提供开箱即用、颜值极高的独立 App，而不是门槛极高的 IDE 插件。
2.  **最后 20% 的绝对控制权 (Direct Manipulation)**：AI 擅长 0-80% 的粗剪（如自动打标记），但对于最后 20% 的微操（精确调整 Zoom 位置、修改光标的物理弹性参数等），“拖拽时间轴和绿框”的效率碾压“用 Prompt 指挥 AI”。**时间轴与可视化交互是不可替代的壁垒。**
3.  **视觉渲染天花板**：我们自主掌控的底层图形学管线（PIXI.js + WebCodecs），能够实时渲染好莱坞级别的 3D Rotato 包装和 Jitter 级独立矢量果冻动效，这是无头自动化脚本极难实时生成的。

这一护城河逻辑，决定了我们目前死磕**“阶段一：时间轴深度交互”与“重绘矢量鼠标”**是绝对正确的战略方向。
